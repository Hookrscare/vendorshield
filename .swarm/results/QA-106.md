## Detailed Verification & Architecture Summary

### 1. Database Migration (`migrations/20260902004500_harden-vendor-persistence.sql`)
- **`is_organization_writer(target_organization_id)`**: Security definer SQL function checking membership with role in `('owner', 'admin', 'member')`.
- **Hardened RLS Policies**:
  - `vendors_insert`: requires `is_organization_writer(organization_id)` and `created_by = auth.uid()`.
  - `vendors_update`: requires `is_organization_writer(organization_id)`.
  - `vendors_delete`: requires `is_organization_admin(organization_id)`.
- **Tenant & Identity Immutability**: Trigger `prevent_vendor_immutable_field_change()` prevents client mutation of `organization_id`, `created_by`, `id`, or `created_at`.
- **Immutable Transactional Audit Logging**: Triggers `audit_vendor_mutation` and `audit_company_settings_mutation` automatically append structured audit records on every mutation.
- **Atomic Admin-Only Company Settings**: Secure RPC function `update_company_settings` validates admin status and updates company fields atomically.

### 2. Repository Layer (`src/lib/insforge/repository.ts`)
- Strict column selection (`VENDOR_COLUMNS`, `COMPANY_COLUMNS`, `AUDIT_COLUMNS`) preventing wildcard projections.
- Deterministic ordering (`name ASC` for vendors, `created_at DESC` for audit events).
- Bounded limits (capped at 200 items).
- Domain mappers (`mapVendorRowToSubProcessorVendor`, `mapCompanySettingsRow`, `mapAuditEventRow`) providing runtime type safety.

### 3. Route Handlers
- **`/api/vendors`**: Authenticated sessions query the tenant repository; anonymous sessions fall back to the read-only in-memory ACME demo. Viewer role returns 403 on POST.
- **`/api/vendors/[id]`**: Scoped strictly to `(id, organization_id)`. Non-admin DELETE returns 403. Viewer PUT returns 403. Cross-tenant IDs return 404.
- **`/api/company`**: Admin/owner authorization required for PUT.
- **`/api/public/[slug]`**: Dedicated projection returning only public-safe company fields and `is_public = true` vendors. Unknown slugs return 404.

### 4. UI Dashboard (`src/app/dashboard/page.tsx`)
- Dynamically detects authenticated session and role.
- For anonymous demo: preserves read-only banner and disables mutation controls.
- For authenticated `viewer`: displays read-only viewer notice and disables add/edit/delete buttons.
- For authenticated `owner`/`admin`/`member`: enables adding and editing vendors, and restricts settings/deletions to admins/owners.
